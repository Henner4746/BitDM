Den Server selbst betreibenRun the server yourself

BitDM braucht zwei Dienste: einen Relay und ein Zwischenlager. Beide liegen im Quelltext, beide laufen auf einer eigenen Maschine. Stand: 29. Juli 2026. BitDM needs two services: a relay and a blob store. Both are in the source, both run on a machine of your own. Last updated: 29 July 2026.

Das Wichtigste zuerstFirst things first

Alle Beteiligten brauchen denselben Relay. Zwei Leute auf verschiedenen Servern können sich nicht schreiben — es gibt keine Weiterleitung zwischen Instanzen. Wer umsteigt, muss die Gegenseite mitnehmen.

Everyone involved needs the same relay. Two people on different servers cannot message each other — there is no federation between instances. If you switch, the other side has to switch with you.

Das ist die häufigste Enttäuschung bei dieser Einstellung, deshalb steht sie hier oben und nicht in einer Fußnote. This is the most common disappointment with this setting, which is why it is up here and not in a footnote.

Ein BefehlOne command

Auf einem frischen Debian oder Ubuntu genügt das. Das Skript fragt nach dem Namen und einer E-Mail, prüft ob der Name wirklich auf die Maschine zeigt, installiert was fehlt und richtet Zertifikat, nginx und Dienst ein. Es ist keine Konfigurationsdatei anzufassen. On a fresh Debian or Ubuntu this is all it takes. The script asks for the domain and an email, checks that the domain really points at the machine, installs what is missing and sets up the certificate, nginx and the service. There is no config file to touch. 

curl -fsSL https://bitdm.net/install.sh | sudo bash

Ein Skript ungelesen in eine Shell zu leiten ist eine Vertrauensfrage, und die richtige Antwort darauf ist Misstrauen. Wer erst lesen will: Piping an unread script into a shell is a question of trust, and the right answer to it is suspicion. To read it first: 

curl -fsSLO https://bitdm.net/install.sh
less install.sh && sudo bash install.sh

Wiederholtes Ausführen ist gefahrlos: das Skript ändert nichts an bestehenden Diensten und öffnet keinen Port ausser 80 und 443, die nginx ohnehin hat. Running it again is safe: it touches no existing service and opens no port beyond 80 and 443, which nginx already has.

Wozu das gut istWhat this buys you

Um Inhalte geht es nicht — die sind Ende-zu-Ende verschlüsselt, und kein Server kann sie lesen, auch unser eigener nicht. Es geht um Verkehrsdaten: wer wann online war, wie viele Umschläge in welche Richtung gingen, wie groß sie waren. Der Relay sieht das zwangsläufig. Wer ihn selbst betreibt, teilt es mit niemandem. This is not about content — that is end-to-end encrypted, and no server can read it, not even ours. It is about traffic data: who was online when, how many envelopes went which way, how large they were. The relay necessarily sees this. Run it yourself and you share it with nobody.

Was du brauchstWhat you need

  • Einen Rechner, der ständig läuft und aus dem Netz erreichbar ist. Ein kleiner virtueller Server genügt. A machine that runs continuously and is reachable from the internet. A small virtual server is enough.
  • Einen Namen darauf und ein Zertifikat. BitDM spricht wss://, und dafür braucht es TLS. A domain name pointing at it and a certificate. BitDM speaks wss://, which needs TLS.
  • Python. Der Relay ist eine einzelne Datei plus ein systemd-Dienst. Python. The relay is a single file plus a systemd unit.

Die technischen Schritte stehen in deploy/README.md im Quelltext, samt Installationsskript. Diese Seite erklärt, was du entscheidest — nicht, welchen Befehl du tippst. The technical steps live in deploy/README.md in the source, with an install script. This page explains what you decide — not which command to type.

Das Zwischenlager nicht vergessenDo not forget the blob store

Anhänge gehen nicht über den Relay. Sie werden verschlüsselt in ein zweites, getrenntes Zwischenlager gelegt; der Relay trägt nur die Anleitung zum Abholen. Wer den Relay aufsetzt und das Lager vergisst, hat einen Messenger, in dem Anhänge scheitern — mit einer Meldung, die nach einem Netzproblem aussieht. Attachments do not go through the relay. They are stored encrypted in a second, separate blob store; the relay only carries the instructions to fetch them. Set up the relay and forget the store, and you get a messenger where attachments fail — with an error that looks like a network problem.

In der App eintragenPoint the app at it

Einstellungen › Empfangen › Serveradresse. Das Feld nimmt wss:// für den Relay; das Lager wird daneben eingetragen. Leeres Feld und übernehmen bringt dich jederzeit zur Voreinstellung zurück. Settings › Receiving › server address. The field takes wss:// for the relay; the store goes next to it. Clearing the field and applying returns you to the default at any time.

http:// und ws:// lässt die App nur im eigenen Netz zu. Nicht aus Bevormundung: ohne TLS liest jeder auf dem Weg mit, wer wann mit wem spricht — und genau das wolltest du ja vermeiden. The app allows http:// and ws:// only on your own network. Not to be paternalistic: without TLS anyone on the path can read who talks to whom and when — which is the very thing you wanted to avoid.

Die UmzugsfalleThe migration trap

Bestehende Unterhaltungen laufen nach einem Wechsel weiter — die Schlüssel liegen auf den Geräten, nicht auf dem Server. Aber ein neuer Kontakt findet dich nur, wenn er beim selben Relay ist. Wer umzieht, sollte das mit allen abstimmen, mit denen er noch schreiben will. Existing conversations keep working after a switch — the keys live on the devices, not on the server. But a new contact can only find you if they are on the same relay. If you migrate, agree it with everyone you still want to message.

Warum wir das anbieten müssenWhy we owe you this

BitDM steht unter der AGPL-3.0. Deren Netzwerk-Klausel verlangt, dass jeder, der mit dem Server spricht, an dessen Quelltext kommt. Ein Messenger, der Metadaten vermeiden will, seine Nutzer aber praktisch auf einen fremden Server zwingt, verlangt genau das Vertrauen, das er zu ersparen verspricht. BitDM is licensed under AGPL-3.0. Its network clause requires that anyone talking to the server can get its source. A messenger that sets out to avoid metadata but in practice forces its users onto someone else’s server is asking for exactly the trust it promises to make unnecessary.
